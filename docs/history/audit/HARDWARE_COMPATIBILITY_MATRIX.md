# Original-machine hardware audit

25 October 2026. **No row below is a runtime pass.** “Adaptable” means an implementation was inspected and contains relevant operations. It does not mean that headers, assembler dialect, workspace, call sites and peripheral timing already form a coherent product. Evidence identifiers link to exact repository, commit, file, symbol and lines in [SOURCE_AND_LICENSES](SOURCE_AND_LICENSES.md#code-evidence).

## Configuration boundary

RO26 `Env/Ursula` selects `Machine=Morris`, `System=Ursula`, `APCS-R`, `ImageSize=4096K`. The chosen machine header sets ARM600, IOMD memory and I/O, VIDC20, FDC711 and PC keyboard. Its `No32bitCode` flag is insufficient evidence about kernel reset: the kernel explicitly enters 32-bit modes. [B1](SOURCE_AND_LICENSES.md#b1) [H1](SOURCE_AND_LICENSES.md#h1) [K6](SOURCE_AND_LICENSES.md#k6)

The historical A440 header explicitly applies to A440/1 and chooses ARM2, IOC-A1, VIDC1a, MEMC1a/MEMC1 memory mapping, FDC1772 and A1A500 keyboard. It is an actual released Apache-noticed file, not a reconstructed guess. The current kernel still contains `hdr/Old/NewSpace`; absence from HdrSrc is **not** absence from the released sources. Export/search-path integration must be verified. [H2](SOURCE_AND_LICENSES.md#h2) [K12](SOURCE_AND_LICENSES.md#k12) [K19](SOURCE_AND_LICENSES.md#k19)

## ARM2 instruction audit scope

Check assembled code and macro expansion, not grep counts. Reachable instructions must conform to the ARM2 set and 26-bit exception conventions. Include SWP/SWPB, MRS/MSR, later multiply/halfword/branch-exchange instructions, coprocessor use, unaligned loads and PC operand/status handling. ARM3 cache operations must be unreachable on ARM2 except through a documented, tested probe. MacArch’s core models SWP as ARM3/ARM250-specific ([M15](SOURCE_AND_LICENSES.md#m15)); emulator acceptance alone cannot replace an instruction-set audit. [ARM hardware PRM](https://www.riscos.com/support/developers/prm/hardware.html).

## Other models are separate acceptance configurations

| Model | Distinction to preserve | Audit position |
|---|---|---|
| A440/1 ARM2 | 4 MiB baseline, MEMC1a/VIDC1a/IOC, WD1772, optional ST506 | Primary configuration; no runtime tests. |
| A440/1 ARM3 upgrade | Cache/CPU timing changes, same original chipset | Second primary variant; no turbo emulation as substitute. |
| A3000 | Same hardware family, different memory/storage expansion constraints | Suitable common subset for second-emulator work. |
| A5000 | ARM3, newer I/O/765-family floppy and IDE | Separate ADFS/configuration tests. |
| A3010/A3020/A4000 | ARM250 integration and different I/O/ROM chip layout | Separate build/packaging assessment. |
| Original A305/A310/A440 | ROM carrier/socket requirements differ from A440/1 | Do not prescribe a universal physical image or carrier. |

MacArch model distinctions come from [M1](SOURCE_AND_LICENSES.md#m1). Historical socket/model documentation comes from [RISCOS.com’s 3.10/3.11 platform page](https://riscos.com/riscos/310/index.php), which contains obvious MB/KB typography errors in its chip-size prose; do not copy those units into engineering specifications. Exact board revisions and wiring remain open.
