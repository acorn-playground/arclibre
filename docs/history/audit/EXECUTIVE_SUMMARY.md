# Open Archimedes ROM: Phase-0 verdict

25 October 2026. Target: **RISC OS 3.11 behaviour on A440/1 ARM2, then ARM3**. Research and documentation only; no ROM was built or run, and no implementation was changed.

**CONDITIONAL GO for a bounded source-recovery experiment; NO-GO for presenting or distributing the current RO26 image as an Archimedes/3.11 replacement.** Prefer a derivative using the published **pre-April-2000 kernel**, original-machine headers, and individually audited desktop components. This is route A, specifically pathway 2 in the brief, with selective reuse of RO26’s integration work. It is not clean-room development.

## Five findings that determine the recommendation

1. **RO26 really has published source.** `Products/All` master is `253a8a2b99705d81033a31ae1174dbf345ed1beb`: 539 component entries, 538 reachable `twentysix` heads, one MIDIPlay access failure. The complete observed branch inventory is recorded in [SOURCE_AND_LICENSES](SOURCE_AND_LICENSES.md#complete-twentysix-ref-inventory). This is a branch set, not a demonstrated reproducible A440/1 product lock.
2. **26-bit application support does not mean an ARM2 kernel.** RO26 kernel `724ffabb…` derives from September 2000 and retains 32-bit reset paths. Commit `b4016e9c…` (4 April 2000) removed substantial old-machine code. Its parent, **`24044755f08dc3b99779833a57eecf3899561ce6`**, retains MEMC setup and 26-bit mode handling. [K6](SOURCE_AND_LICENSES.md#k6) [K11](SOURCE_AND_LICENSES.md#k11) [P1](SOURCE_AND_LICENSES.md#p1) [P2](SOURCE_AND_LICENSES.md#p2)
3. **Original-machine support is substantial but disconnected.** Real CAM/RAM-detection code, VIDC1 palette operations, keyboard and WD1772 routines survive. Historical `HdrSrc` commit `c9113ab…` explicitly names A440/1 and selects the right chipset. These are reusable candidates, not a working assembled configuration. [K3](SOURCE_AND_LICENSES.md#k3) [K4](SOURCE_AND_LICENSES.md#k4) [K16](SOURCE_AND_LICENSES.md#k16) [K17](SOURCE_AND_LICENSES.md#k17) [A2](SOURCE_AND_LICENSES.md#a2) [H2](SOURCE_AND_LICENSES.md#h2)
4. **The desktop is available as source, but its semantics need work.** Wimp, Desktop, Filer, BASIC, FileSwitch, fonts and associated libraries were located. Even Wimp’s `RO310` configuration enables later UI extensions. No application or desktop compatibility percentage has been measured. [W1](SOURCE_AND_LICENSES.md#w1) See the [component review](SOURCE_AND_LICENSES.md#component-classification) and [acceptance corpus](COMPATIBILITY_TEST_PLAN.md).
5. **Capacity and provenance are independent gates.** RO26 selects a 4 MiB image; the original 3.1 baseline is 2 MiB. MEMC’s high-ROM address window is larger than 2 MiB, so this is a board/storage and footprint problem, not proof of an architectural impossibility. MacArch’s core can load variable-size images, while its library importer restricts them. Most inspected repositories carry Apache terms, but FPASC and SpriteExtend have explicit additional terms, and the final resource manifest is not cleared. [B1](SOURCE_AND_LICENSES.md#b1) [M2](SOURCE_AND_LICENSES.md#m2) [M3](SOURCE_AND_LICENSES.md#m3) [L1](SOURCE_AND_LICENSES.md#l1) [L2](SOURCE_AND_LICENSES.md#l2) [Capacity evidence](BOOT_PATH.md#rom-capacity-and-packaging).

## Biggest blockers and next action

There is no verified ARM2 build closure, no complete licensed payload manifest, no measured trimmed footprint, and no lawful 3.11 differential run. The original-machine kernel and later desktop memory/resource assumptions must be reconciled; booting alone resolves none of the application requirements. A proprietary build-time toolchain is also still the documented route.

Review [FIRST_BOOT_EXPERIMENT](FIRST_BOOT_EXPERIMENT.md): **one assembly/architecture closure test of the pre-conversion kernel**, before attempting a bootable ROM. Passing it would justify further engineering investigation only. Failure due to missing public dependencies would weaken the derivative route; an assembler/configuration failure alone would not establish hardware infeasibility.

A complete clean-room implementation avoids dependence on Acorn code only if performed under the protocol in [SOURCE_AND_LICENSES](SOURCE_AND_LICENSES.md#route-b-clean-room-protocol); it adds a very large desktop and behavioural-reconstruction burden. It is not presently the preferred fallback to a solvable source-integration problem.

All eight requested reports are supplied. **The brief’s full feasibility acceptance is not yet closed:** exact shipped 3.11 inventory, final asset rights, buildability, footprint and real-software behaviour remain explicitly unresolved. [OPEN_QUESTIONS](OPEN_QUESTIONS.md) records what would change this verdict. No owner input is needed to read this audit; future private baseline testing needs a lawfully supplied 3.11 ROM and the selected software.
