# Source archaeology, provenance and licences

25 October 2026. **Scope:** public released-source research, source-level inspection and read-only MacArch inspection. No ROM build, black-box reference run, proprietary ROM/game acquisition, distribution or implementation change. Public source repositories contain pre-existing binary assets (fonts/sprites and a labelled FPE blob); they were not copied into these deliverables or certified as an all-source product.

## Reading the evidence

- **V — verified file/metadata:** directly inspected Git objects, text files or local committed source. This verifies what the source says, not that it runs.
- **A — author/documentation statement:** project page, manual or published build instructions. Attribute it; do not turn it into a measured result.
- **I — inference:** engineering judgement from the evidence, explicitly provisional.
- **U — unresolved:** failed access, incomplete licence/input closure or behaviour that requires testing.

All substantial code findings use the [code evidence register](#code-evidence) below. Full SHA-1 commits are identifiers, not a statement about cryptographic trust or publisher identity. The observed server was public and required no credentials. Its API advertised loopback clone URLs; usable HTTPS URLs came from the published RO26 instructions and successful Git access, not from assuming the loopback addresses were valid public hosts.

## Exact source discovery and relationship to ROOL

**V:** `https://gitlab.4corn.co.uk/Products/All.git`, `master`, **`253a8a2b99705d81033a31ae1174dbf345ed1beb`**, has 539 `.gitmodules` entries. Of those component URLs, **538 returned a `refs/heads/twentysix` head**. `RiscOS/Sources/Audio/MIDIPlay` did not: Git received an authentication prompt and failed without credentials. No credentials were tried. The parent product’s observed branch list contains master only. [Pinned manifest](https://gitlab.4corn.co.uk/Products/All/-/blob/253a8a2b99705d81033a31ae1174dbf345ed1beb/.gitmodules).

This is therefore a **published multi-repository branch set**, not binary-only. It includes an actual build environment, component product files and source. It is **not demonstrated here as a fully reproducible C1 tree**: branch tips differ from parent gitlinks, there is no verified C1 release lock, some branches are placeholders, tools are externally supplied, and no build was run. A branch existing does not prove it contains a component implementation. Example: `Internat/Territory/UK` contains only `rm/.gitignore`; the product's `UK` is actually generated by `TerritoryModule`. [B3](SOURCE_AND_LICENSES.md#b3)

**V:** RO26 Kernel `724ffabb1ce232949bbcafec10ea59aa6d62891e` has parent **`0c77dd31591ae2605fb4df6a3daf801ddd136765`**, dated 8 September 2000 in the mirrored history. Its own change modifies only `Version` (six lines added/six removed), not original-chipset support. [RO26 kernel commit](https://gitlab.4corn.co.uk/RiscOS/Sources/Kernel/-/commit/724ffabb1ce232949bbcafec10ea59aa6d62891e). The author's account of a pre-HAL kernel is consistent with the selected age, but **pre-HAL is not pre-32-bit-kernel**.

**V:** conversion commit **`b4016e9c1087375ea105d5d5ad365d0f5afc0025`**, dated 4 April 2000, changes 80 files, removing 7,804 lines and adding 2,675; its subject is “32-bit Kernel.” Its immediate parent **`24044755f08dc3b99779833a57eecf3899561ce6`** retains original MEMC and 26-bit startup branches. [Conversion diff](https://gitlab.4corn.co.uk/RiscOS/Sources/Kernel/-/commit/b4016e9c1087375ea105d5d5ad365d0f5afc0025), [P1](SOURCE_AND_LICENSES.md#p1), [P2](SOURCE_AND_LICENSES.md#p2). This is a more targeted starting point than blindly using the RO26 tip.

**V:** HdrSrc history contains the Apache-noticed original `hdr/Machine/A440` at **`c9113ab79d9ca2ccc49a9b7518911132ca9ffa1b`** (cleaned 3.60 import, stored date 5 November 1996). It explicitly applies to A440/1. The `twentysix` HdrSrc head is **`403c6dd8bce92d0629634cbf57f68f43b2f30d38`**, a later releasable header set. Kernel history includes a cleaned source import at `3da129d209b2c78d19f6c28d9a8f15cd6f1c3bfc`; another early import's message explicitly notes a real commit date different from its historical timestamp. **Do not mistake reconstructed historical dates for publication dates or assume omitted pre-release history is publicly available.** [H2](SOURCE_AND_LICENSES.md#h2) [Header history](https://gitlab.4corn.co.uk/RiscOS/Sources/Programmer/HdrSrc/-/commits/twentysix).

**A/U:** RO26 calls this released ROOL-derived code. The mirror contains component histories and Apache notices consistent with that account, but live authoritative upstream object equality could not be independently verified: official Git redirected to a 503 page. Accordingly this report establishes the mirror's exact contents and notices, not a complete independent chain-of-title certification for every historical file.

## Release obligations and asset audit

For Apache-covered derivative files, keep the licence, applicable attribution/notices, and identify changes as required by section 4; preserve any NOTICE obligations present in the actual input set. For FPASC and applicable SprExtend portions, also retain BSD notices/disclaimers and the IJG attribution required for binary distribution. Apache does not grant trademark rights. The final component bill of materials must include source URL/commit/path/hash, asset author/origin, licence scope, local changes, generation recipe and output inclusion location. [Apache terms](https://www.apache.org/licenses/LICENSE-2.0), [L1](SOURCE_AND_LICENSES.md#l1), [L2](SOURCE_AND_LICENSES.md#l2).

A concrete exception to “everything in a repo is automatically safe to republish” is ROMFonts' archived Adobe glyph documentation carrying its own copyright/legal-notice reference. It is research documentation, not proven ROM payload. Do not inflate it into a fatal font blocker, and do not redistribute it indiscriminately under the root Apache label. [L4](SOURCE_AND_LICENSES.md#l4) For font/sprite bytes actually selected by a product, inspect scope and provenance rather than assigning a new licence based on convenience.

## Route B clean-room protocol

This audit has inspected **licensed derivative source**. It does not certify any future implementation based on this analysis as clean-room. If route B is selected, create distinct analyst/specification and implementation roles with documented access controls; do not simply rename this port a reimplementation.

1. Analysts may use approved published API/hardware specifications and lawful private black-box runs. Record exact source/licence/edition and the legal basis for access. A lawyer should approve any method involving licence restrictions, interoperability exceptions or protection mechanisms before it is used.
2. Write original interface specifications and tests describing inputs, outputs, register/flag effects, public memory contracts, error semantics and hardware sequences. Keep observed 3.11 quirks separate from documented rules. Exclude proprietary code, disassembly/decompilation, ROM byte sequences, artwork/fonts and implementation-derived pseudocode.
3. A reviewer screens each specification/test/fixture for provenance and unnecessary copied expression. Only approved behaviour specifications cross to implementers. Implementers work from those specifications and original/cleared assets; maintain access and contribution logs, including prior exposure disclosures.
4. Analysts run lawful differential tests privately. Return behaviour-focused discrepancy reports, not protected source or copied internal routines. Public test fixtures contain original material; do not publish ROM dumps, reference snapshots, copyrighted screen contents or trace corpora containing implementation bytes.
5. Independent review checks the final implementation, assets, contributor representations and distribution manifest. A clean-room process reduces certain provenance risks; it is not a universal legal guarantee or a substitute for API, patent, trademark and contract analysis.

Specialist questions include jurisdiction-specific interoperability/observation rights, the reference-ROM licence and permitted copies, contract restrictions, copy-protection/anti-circumvention, copyright in manuals/tests/fonts/artwork, APIs and interface expression, and branding. The [UK observation provision](https://www.legislation.gov.uk/ukpga/1988/48/section/50BA) and [interoperability provision](https://www.legislation.gov.uk/ukpga/1988/48/section/50B) are questions for advice, not blanket permission for a global project. No protected-game bypass is proposed.
